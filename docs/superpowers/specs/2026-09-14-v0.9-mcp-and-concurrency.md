# v0.9 design: local MCP and crash-safe coordination

## Problem

v0.8 provides a secure mediated context path, but callers must know the bridge CLI and file contracts. Concurrent local processes can also read the same state revision and silently replace one another. Oracle has a stronger browser lease, while Codex with ChatGPT exposes a standard MCP surface at the cost of a daemon, OAuth, and a tunnel.

## Decision

v0.9 exposes the safe read side as a dependency-free STDIO MCP server and protects every persistent state commit with an exclusive local lease plus optimistic state revisions.

The MCP server is project-scoped and local. It opens no port, accepts no network connection, stores no credential, sends no Chat message, executes no caller-supplied command, and does not write bridge state. Codex remains the mediator between an ordinary Chat and the workspace.

## MCP tools

| Tool | Result | State effect |
|---|---|---|
| `bridge_status` | Privacy-safe lifecycle state and next action | None |
| `bridge_health` | Checkpoint, receipt, transport, continuity, and cost health | None |
| `bridge_lease_status` | Current write contention without PID or lease secret | None |
| `bridge_dry_run` | Optimized request, source token attribution, reuse decision | None |
| `bridge_pull_context` | Bounded file lines, literal search, filtered diff, or receipt | None |

Every tool has a closed JSON Schema and read-only MCP annotations. `bridge_pull_context` retains all v0.8 path, symlink, secret, binary, file-size, line-count, result-count, hash, and token limits. Tool errors are returned as bounded structured MCP errors without stacks or local identity.

## Concurrency protocol

The runtime directory contains a transient `.write-lease/owner.json` while a commit is active. Directory creation is the exclusive acquisition primitive. The owner record contains a random lease id, PID, process start estimate, operation name, acquisition time, and heartbeat.

- A live lease fails closed with `BRIDGE_BUSY` after a bounded wait.
- A lease is stale only when its heartbeat is older than the stale interval and its PID is no longer alive.
- Stale and released lease directories are atomically renamed before deletion, so a process cannot delete a replacement owner's lock.
- Release verifies the random lease id before removing anything.
- Every state snapshot has a monotonic `state_revision`.
- Commit compares the caller's revision with the current revision while holding the lease. A mismatch returns `STATE_CONFLICT` instead of overwriting newer state.
- The journal entry is written before the atomic state replacement, allowing recovery after a crash between those operations.
- Older v0.8 state without a revision enters v0.9 at revision zero and upgrades on its next commit.

## Configuration

The server follows the Codex STDIO MCP configuration documented by OpenAI. It is configured per project so `cwd`, the workspace root, and `.codex/codex-bridge-chatgpt` all identify the same checkout. See `docs/codex-mcp-config.example.toml` and `references/local-mcp.md`.

## Non-goals

- No remote MCP, public HTTP endpoint, Cloudflare tunnel, OAuth server, or connector daemon.
- No MCP write, shell, test execution, browser control, send, adoption, or artifact-application tool.
- No automatic edit of the user's global Codex configuration.
- No claim that ChatGPT web can directly access a local STDIO server.

## Acceptance

- Existing lifecycle and v0.8 tests remain compatible.
- Two concurrent stale writers cannot both commit.
- A dead stale owner is recoverable and a live owner is never removed.
- MCP initialization, tool listing, tool calls, notification handling, and newline-delimited STDIO work without third-party dependencies.
- MCP calls cannot mutate the state file or create a context response file.
- The packaged copy passes the full test, Doctor, verifier, and Skill validation gates.
