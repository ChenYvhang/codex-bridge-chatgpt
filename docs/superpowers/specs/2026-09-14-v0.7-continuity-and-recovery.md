# v0.7 Continuity and Recovery Design

## Goal

Complete the third experience-improvement batch by making long-running bridge state understandable, reducing repeated user interruptions, and preserving useful Chat context when the designated conversation is lost.

## Decisions

1. `bridge health` is the detailed read-only surface. It reports integrity, age, pending work, capability, receipt, and local cost information while omitting the stored Chat reference and absolute workspace root.
2. `bridge questions` deduplicates normalized question text and separates user decisions from Codex answers and local checks. The user sees one combined prompt.
3. `bridge recovery-export` creates a portable, hash-bound, secret-scanned recovery packet only when the checkpoint covers the latest completed round and there is no in-flight mutation.
4. Recovery packets omit transcript history, account/Chat identifiers, absolute workspace paths, rejected entries, and volatile `local_fact` entries. The default budget is 2,000 approximate tokens and the hard ceiling is 2,500.
5. Export is preparation only. Chat selection, one-time sending, acknowledgement verification, and state migration remain explicit lifecycle steps.

## Failure behavior

- Tampered or missing checkpoint/receipt files block recovery export.
- Stale checkpoints block export rather than silently losing a completed round.
- Likely secrets and oversized packets block export before the destination file is created.
- Existing output paths are not overwritten.
- Question routing never supplies credential values or performs external side effects.

## Compatibility

The state and exchange schemas remain version 2. Existing v0.4-v0.6 runtimes remain readable. New commands consume existing state without a migration.
