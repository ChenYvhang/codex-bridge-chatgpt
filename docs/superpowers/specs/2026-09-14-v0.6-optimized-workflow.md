# v0.6 Optimized Workflow Design

Date: 2026-09-14

## Goal

Remove routine handoff assembly, stop oversized requests before transmission, and avoid paying for a result that is already locally verified under the same state.

## One-command preparation

`bridge start --spec <file>` accepts a profile, objective, and context delta. It compacts the delta, evaluates the send budget, checks for a reusable exchange, begins the next monotonic round, writes the canonical request, assigns its idempotency key, and leaves the state in `AWAITING_SEND`.

Failures before round creation do not mutate bridge state. A failure after creation aborts the allocated round with a journal reason rather than leaving an ambiguous active request.

## Context compaction

The optimizer trims leading and trailing whitespace, removes empty values, deduplicates through a normalized comparison key, enforces list-length limits by field, and reduces receipt and checkpoint anchors to identity plus SHA-256. The retained string keeps its original internal whitespace, which may be significant for code or logs. Ordering remains stable so the first occurrence wins. A field over its limit is rejected rather than silently truncated.

## Budget enforcement

`bridge optimize --request <file>` reports before and after estimates, savings, duplicate rate, protocol share, and suggestions. It can write the optimized request to a chosen path. Both `start` and the low-level `prepare` gate block requests above 3,000 approximate input tokens.

## Verified-result reuse

The bridge hashes semantic request content without round-specific identity. Reuse is allowed only when the most recent exchange completed successfully and its semantic hash, workspace fingerprint, and input checkpoint hash all match current state. The command returns the existing result path and does not create or send a new round. Any workspace or checkpoint change disables reuse.

## Acceptance criteria

- One command produces an optimized, valid request in `AWAITING_SEND`.
- Empty and duplicate delta fields do not consume outbound tokens, and unique evidence is never silently discarded.
- Oversized requests fail before sending even through low-level commands.
- Reuse cannot cross workspace or checkpoint changes.
- Existing v0.5 commands and stored exchanges remain valid.
