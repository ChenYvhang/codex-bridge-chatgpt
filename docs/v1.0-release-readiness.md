# v1.0 release readiness

This file separates the locally reproducible candidate from a publishable GitHub release.

## Verified locally

- State schema 3 scopes a bridge to one normalized Chat and one stable canonical workspace identity; current repository and checkpoint hashes independently guard result reuse.
- Schema-v1/v2 migration, Chat replacement, and project MCP setup have guarded transitions and negative tests.
- Context-source accounting, revision-based quiet reads, privacy-safe support output, and a dependency-free local STDIO MCP are covered by deterministic tests.
- Repeated release builds are byte-identical. An extracted archive runs Doctor and a JSON-RPC initialize, tool-list, and read-only tool-call smoke test.
- The old live Chat visibly recalled `ORCHID-27` and echoed a v1.0 scope in round 7, but its Copy action did not produce verifiable clipboard bytes. The provisional local completion was invalidated; the active checkpoint was restored to round 5 and the bridge was paused. See [live evidence](live-e2e-validation.md).

## Gates for a tagged release

- Build the release archive from its exact reviewed, clean commit. The first local candidate (`rc1`) was built from a working tree at the original upstream commit, so it is only a historical test artifact.
- Require a successful CI matrix on Linux, macOS, and Windows against the final commit.
- Complete a fresh v1.0 end-to-end transfer with verifiable response bytes, including an accepted and a rejected artifact, and record the sanitized manual matrix at that commit. Logged-out, wrong-Chat, uncertain-send, interrupted-response, and recovered-Chat cases are not all evidenced yet.
- Confirm packaging, hashes, and manual evidence refer to the same commit. Publishing source and creating a tagged release are separate actions.

The source is public on `main`; a tagged release still requires the manual end-to-end evidence above. The release Doctor reports contract readiness and whether its source tree is clean through `publishable`. That field does not establish cross-platform CI or manual evidence.
